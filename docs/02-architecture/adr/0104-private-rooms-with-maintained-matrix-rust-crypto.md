# ADR-0104: Explicit private rooms with maintained Matrix Rust crypto

Status: Accepted

Provider activation, security acceptance, combined-stack runtime and real cross-device browser protocol qualification are pending. This decision does not authorize production activation or governance completion.

## Decision

Create new Conversations-owned rooms with immutable `content_mode=matrix_e2ee`. Existing conversations keep `server_readable`; ordinary create/update commands cannot select private mode or silently convert a room. The web private-room route uses exactly pinned `matrix-js-sdk` 43.0.0 and `@matrix-org/matrix-sdk-crypto-wasm` 18.7.0 (actual registry Apache-2.0), including maintained Rust Olm/Megolm, SAS, cross-signing, encrypted IndexedDB and secret storage/key backup. Application code implements authority and trust gates, no cipher or custom key agreement. Federation's separately disclosed plaintext bridge must reject this conversation mode.

IdentityAccess owns immutable tenant/user/native-principal mapping and exact current K session/device delegation. Standard device-bound Matrix password login with refresh tokens and native `whoami` establishes a real crypto device. Device-less Synapse admin login is only room-control authentication and cannot impersonate a participant crypto device. Client access credentials have a maximum 180-second native lease; server credentials and refresh tokens are AEAD-encrypted using the existing IdentitySecretBox and never expose provider/admin passwords. Client access-token DTOs are private, no-store and Inspect-redacted. Message keys, local store passwords, private cross-signing keys and recovery material remain client-held. Public-key upload proxies only exact public Ed25519 objects, refuses replacement of existing native signing public keys and uses current retained step-up authority for native UIA. A consumer-owned Governance projection takes the tenant fence before credential claims and refuses new client delegation for an approved/in-progress governed user erasure.

A configured device-less control principal remains an explicit room member with no device, master, self-signing or user-signing crypto keys. Native control checks `whoami`, Synapse device inventory and standard `/keys/query`. The SDK fetch boundary rejects control crypto keys before ingestion. Every send and plaintext projection obtains a fresh native control-key query and checks cached SDK control devices. Native provider key poisoning and compromised client code are externally qualified threat boundaries, not assurances obtained from DTO validation.

Participants must verify every human identity through matching maintained SDK SAS; SDK signed-device TOFU alone is insufficient. Encrypted to-device key envelopes permit only current exact room participants and verified own devices, never control/removed/unknown identities. Existing public identity or secret storage prevents automatic reset. New setup requires an explicit saved-recovery confirmation. Recovery and verified second-device flows use maintained SDK APIs. Web Locks permit one SDK machine per encrypted store. Decrypted timelines and draft/outbox text use MemoryStore; encrypted IndexedDB always requires a local password. A lock clears displayed/in-memory plaintext and SDK references; forgetting removes that device's whole private-room crypto store. Logout attempts deletion of stores registered in this page lifetime. Previous browser profiles, offline devices, recipient copies and backup versions are not silently certified deleted.

## Owner boundaries and protocol

IdentityAccess owns `matrix_identities`, `matrix_client_sessions`, the ready-only `Accounts.matrix_identity_view/2`, current-session `matrix_client_session/1` and a consumer-owned provisioning port. `issuer` is the canonical HTTPS homeserver origin; `matrix_user_id` binds a separately configured native server_name and immutable tenant/user UUIDs. Federation compares all three plus exact tenant/user, never email or URL-host inference.

Conversations owns `private_matrix_rooms`, initial 2–20 explicit human participants, historical potential-author lineage, membership epochs, control, native alias recovery and conservative erasure. Identity lifetime capacity is 1,000 mappings and 10,000 device sessions per tenant; private-room lifetime capacity is 1,000 rows. Retained Governance tenant, owner capacity/tenant, sorted participant User write exclusion, current actor Device/Session and conversation/room/membership locks gate current commands in that order. One absolute monotonic deadline covers lock waits, every native request and receipt delivery. Current human workspace eligibility withdrawal fences room membership/epoch locally under retained User authority and queues native cleanup without provider/Governance reentry. Room reservations and a first-attempt marker commit before provider effects; later alias 404s remain recovery-only after an uncertain ACK. Exact immutable provider origin, independent server_name, control creator, application lineage and invite-only/non-federated/joined-history privacy settings must match before recovery or purge. Control effects retain authority. Removal first persists membership withdrawal and a generation/epoch rekey fence; unknown native ban ACK keeps all sends fenced until actual ban-state confirmation. Remaining clients discard their outbound Megolm session before subsequent sends. Old keys already received cannot be retracted. Adding participants, guests, encrypted media/files, federation encryption and native mobile private-room UX are outside this bounded source milestone; create a new explicit room for a new participant set.

ConversationContent owns opaque native Megolm events and durable pending send intents. It accepts a closed bounded 65-KiB encrypted envelope, never text or client author lineage. Trusted current K User/Device/Session attribution and native room/sender/content receipt validation establish authorship. Capacity is 10,000 lifetime rows per room, 100,000 per tenant and 32 unresolved intents per author session/room. Current authority remains retained through native send/receipt. The SDK wrapper captures an immutable send epoch/generation before encryption; a change before first dispatch rejects the already encrypted envelope rather than relabelling it. Stable transaction IDs plus exact ciphertext fingerprint preserve retries and unknown ACKs; changed input, erased intents or old epochs/generations refuse. Current-session replay resumes only that session's current-generation pending intents. Remaining participants can read authorized earlier retained generations. Allocation can leave pending sequence holes, so browser reconciliation replays bounded history from zero instead of treating an allocated high sequence as proof that all earlier ACKs arrived. SDK decryption/integrity/trust shields and owner event IDs gate plaintext display; SDK scrollback loads earlier ciphertext under current authority. Responses are bounded to 8 MiB.

Private conversation mode refuses ordinary plaintext messaging, recording/calls, uploads/whiteboards/documents, server search/summary/moderation capture and plaintext export. Room titles, membership, provider principals, ciphertext sizes/timing and attribution remain server-readable; this is message-text E2EE, not metadata privacy or encrypted calls.

## Governance and release

Every historical participant is conservatively a potential original author, even after removal. Governed erasure of any such author fences and purges the entire derived private room and every retained opaque event/pending intent; unrelated rooms survive. Unknown lineage or any applicable legal hold blocks deletion. A native purge is executed under the retained hold fence and requires actual asynchronous delete-status completion. ConversationContent wipe uses a Conversations-owned command/receipt port and verifies retained room/generation/native purge/time facts, with the Governance hold fence retained.

An enrolled Matrix identity creates a durable erasure barrier even with zero private rooms: generation fencing atomically reseals retained authentication, in-flight issuance cannot restore ready state, and cleanup retains exact stable-device obligations. Native room purge does not prove all-version key-backup erasure, remote/recipient copies, local encrypted crypto-store cleanup or offline device deletion. `key_cleanup_state` remains durably `unconfirmed`; no API/manual checkbox sets it confirmed, no room reaches `erased`, and Governance completion remains pending. Standard native cleanup proof may expire across provider restart; missing proof remains pending. See the operator runbook. Provider controls stay configured for cleanup when creation flags are OFF.

Additive migrations 20261006001000/01100/01200 retain tuple-bound FKs and refuse rollback on every retained identity, device proof, private-mode conversation/room, ciphertext or tombstone. Release fingerprints include IDs only, never keys/ciphertext. `private_rooms_v1` covers owner retained rows and active device/purge jobs in image, Kubernetes and Proxmox compatibility metadata. No baseline finding or dependency exception is introduced. The exact isolated-parent manifest transition authorizes only these source DTO/table/facade additions; Root must refreeze its own delta when composing onto the qualified current Member parent.

## Evidence and qualification

Initial isolated source qualification executed warnings-as-errors backend compilation, fresh additive migrations and focused owner tests: 21 cases passed, plus four actual Postgres connection race cases after adding late login ACK versus zero-room erasure. Eleven real native-adapter cases passed through synthetic pinned HTTP transport. They cover recovery-only 404s, immutable ownership/privacy, current control absence, deadline refusal and pending cleanup; they do not establish live Synapse behavior.

The real pinned Matrix43/Rust18 Node harness passed two public-key identity/control trust cases and one actual `encryptEvent` membership-epoch race. The fixture explicitly publishes generated public signatures and uses the maintained CryptoApi verification state; it does not qualify peer SAS, browser stores or provider interoperability. Normal web test configuration also executed these Node cases alongside cache boundaries. Fourteen drawing/menu/export/history cases passed with explicit English, and production `tsc`/Vite/PWA/assets passed all unchanged budgets: 9,752,890 raw and 2,944,733 gzip JS/CSS bytes. The exact pinned Excalidraw production import-map transform removes only 55 unsupported locale modules, fails on upstream byte drift and preserves the engine/embedded English. No asset exclusion or budget increase was introduced.

Rust WebAssembly is separately measured at 7,826,886 raw / 2,092,621 gzip bytes, SHA256 `56541b4fd52f2d847c2706421f3ab816e8a92aca289290cabdfb815a8ea24a55`. The current budget checker measures JS/CSS only; this binary cost is additional. Matrix/Rust/WASM are absent from the initial static entry closure and the worker does not precache them at install. Existing exact media-type/public hashed cache rules never cache authenticated private APIs or delegated credentials. Native/browser loading and production static MIME remain combined runtime gates.

Dependency lock-only resolution and production audit reported zero vulnerabilities with actual registry version/license/integrity receipts. Initial compile, fixtures and build failures remain preserved. Individual architecture/contract gates and independent source review bind exact snapshots. The separate live browser gate is authored but unrun: it must execute real maintained Rust crypto against disposable Synapse identities, SAS, zero-control responses, ciphertext-only capture, unknown ACK, recovery, actual member removal and key poisoning. Security review, combined current-parent tests, real cross-device/browser/mobile behavior, provider configuration and backup/client-store inventory remain activation gates. Creation flags stay OFF and unknown key-cleanup proof remains durably pending.
