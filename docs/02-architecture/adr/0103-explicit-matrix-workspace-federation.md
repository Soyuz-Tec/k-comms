# ADR-0103: Explicit Matrix workspace federation

Status: Accepted

Date: 2026-10-05

## Decision

Use a separately configured maintained Matrix/Synapse homeserver for standards-backed server federation. K-Comms uses the standard Matrix v3 client-server endpoints through its existing DNS-pinned, TLS-verifying bounded HTTP transport. Matrix implements server discovery, federation authentication, event authorization and signing; K-Comms does not implement a custom cryptographic federation protocol.

The default is OFF. Enabling requires an operator-reviewed provider qualification flag, one pinned public HTTPS DNS origin, canonical server name, a dedicated non-admin bridge account token, declared local residency and an independent AES-256-GCM envelope key. The flag is an operator declaration and is not a live-provider receipt. Secrets stay in secure server configuration or private files; no API returns the token, an admin credential, a command body envelope, or private provider receipt.

Conversations owns five new tables in migration 20261006000900: tenant-bound trust allowlists, attached rooms, participant consent, bounded durable commands, and content-free event receipts. Foreign User/Session/Tenant authority comes through exact owner facades. Messaging remains the owner of normal K-Comms message bodies and Devices. The bridge never inserts foreign Messaging rows, impersonates a User/Device, or automatically exports existing K-Comms messages.

The new web panel queues explicit plaintext bridge messages and renders bounded authorized Matrix room history. Its disclosure states that the configured and approved remote homeservers can read and retain content. Transient command bodies are encrypted until terminal receipt or cancellation; incoming message text is returned transiently after current admission and is never persisted as a K-Comms message, indexed, summarized, or published in the normal message outbox. The local metadata export explicitly says local_metadata_only, bounds receipts to 1000, marks truncation, and declares incoming_content_persisted_locally false. This does not claim a complete remote content export.

Only an exact lowercase DNS server in a current administrator allowlist may receive an invitation. An administrator records declared residency and a reviewed cross-workspace processing reason. This declaration is not an independent geographical verification. Matrix IDs bind to exact domains, never email aliases. Invite-only room state, a server ACL restricted to the local and approved remote server, forbidden guest admission and bridge-controlled invite/state/encryption permissions prevent untrusted autojoin. Remote acceptance is observed only from actual joined-member state. Local members separately accept the plaintext disclosure; withdrawal is irreversible for that attached room. A disabled trust fences existing rooms; re-enabling a domain cannot resume them.

Each retained room binds its immutable canonical HTTPS homeserver origin separately from the Matrix server_name and retains its original bridge control principal. All cleanup requests compare these three retained values before native HTTP; missing evidence or changed credentials retain a pending obligation instead of selecting a current-config replacement. Cleanup additionally verifies original creator, lineage sender and bridge-controlled power state, while allowing encryption state to appear without capturing plaintext. Changed configuration refuses provider effects and retains existing cleanup obligations; it cannot redirect an old room to another provider. IdentityAccess owns the exact ready-only MatrixIdentityView lookup, backed by dedicated immutable issuer/tenant/K-user mappings from ADR-0104's shared identity owner source. Federation uses Accounts.matrix_identity_view/2; it never provisions identities inside retained Federation locks, reuses OIDC FederatedIdentity, or trusts email. Matrix client sessions and client-held Matrix Rust SDK encryption remain ADR-0104. This bridge refuses any m.room.encryption state or m.room.encrypted event before plaintext capture or sending. Existing private rooms are never converted to plaintext federation rooms. The current Conversations owner admission guard refuses any encrypted or unknown content_mode before bridge creation, send, invite or read; cleanup retains previous obligations. ADR-0104 creates a new ordinary Conversation UUID with matrix_e2ee mode, and Root must union its additive ConversationView/contracts and encrypted-client UI disclosure.

## Current proof, concurrency and uncertainty

The finite 15-second effect budget starts before admission locks and covers lock/statement waits, DNS, TLS, HTTP and result recording. The order is Governance tenant seal FIRST, quota/Tenant, sorted local human Users FOR NO KEY UPDATE, current actor Device/Session, Trust, Conversation, Room, Participant and Command. IdentityAccess owns the narrow FederationActorLockQuery and lock_federation_actor/1. It avoids a FOR SHARE to NO KEY UPDATE upgrade. The provider effect retains exact current authority and consent on the same transaction. Incoming capture verifies every joined principal is currently allowed. Membership-held and User-held lifecycle contributions fence local consent and queue cleanup; they never reenter Governance, acquire another User/Conversation or call a provider. Ordinary logout leaves accepted offline consent intact but its queued current-session commands cannot execute with stale proof.

The separate first-attempt marker, stale-command cancellation and bounded reconciler also use finite 15-second lock/statement transaction budgets. Terminal create commands cannot be prepared again. CreateRoom has no Matrix transaction-id endpoint. A durable owned alias and bridge lineage state are allocated before creation. The first-attempt marker commits independently before the effect. Retries resolve that exact alias and validate creator/lineage; an unresolved lost acknowledgement remains uncertain and cannot blindly create another room. Message sends and redactions use stable Matrix transaction IDs. Redaction also commits its separate first-attempt marker before I/O: only that first attempt may PUT, and uncertain acknowledgement or crash recovery is read-only event observation. An unresolved observation remains pending; it never claims remote deletion. A client-supplied UUID scopes send idempotency to the tenant, room and actor; changed payload with the same key is refused. After withdrawal an uncertain send is recovered only from the bridge's standard unsigned.transaction_id metadata on bounded room-history pages. Its body is never resent to discover its outcome; an absent bounded search cannot establish global absence.

## Governance, retention and rollback

Governance preparation fences exact room or user scope and persists cleanup jobs before its completion barrier. User deletion preserves other participants' consent. Legal holds prevent destructive remote cleanup. Owned event redaction is checked from actual redaction metadata; member absence is checked from joined-member state. These are local homeserver observations. Matrix redaction or leave does not prove deletion of every federated replica, attachment, backup or provider-held copy, so remote deletion remains unconfirmed and Governance completion remains pending. Local tombstones, encrypted provider lineage and content-free receipts are retained for follow-up. The UI never presents a local leave/redaction as completed remote deletion.

Cleanup-only jobs retain old obligations and may recover an owned room alias, redact an owned event or remove an exact principal. They cannot restore consent, create a new room, retry a body after withdrawal or resume synchronization. Provider-disabled, expired/invalid bridge credentials, unresolved aliases, unknown send outcomes and remote uncertainty remain pending. Close waits for other cleanup commands; the bridge cannot leave before its owned redactions are processed.

Down migration uses literal owner-only inventories and refuses when any of the five tables retains rows. Runtime rollback to a binary lacking workspace_federation_v1 refuses retained Federation rows and runnable Federation jobs. Tenant fingerprints include all five owner inventories. Existing protected migrations, baseline exceptions, manifest enforcement and canonical parent contracts remain unchanged. The original pending Member transition remains preserved in the immutable FAA parent and is not claimed protected. This isolated Federation descriptor declares only its exact own widening from the frozen FAA manifest. Root composes the protected transition after actual Member qualification.

## Qualification status

This ADR accepts the ownership and protocol design. It does not claim completed live federation, geographical compliance, private media/E2EE, software runtime qualification or production readiness. Backend/provider-protocol/HTTP/web lifecycle, migration down/up, concurrency, erasure and rollback tests are authored source and remain UNRUN until the main agent grants CPU and merges the shared IdentityAccess source. No provider credential or remote effect was used while authoring this source. Source/static validation receipts must identify the exact checkpoint independently of runtime evidence.
