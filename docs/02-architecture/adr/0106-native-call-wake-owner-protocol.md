# ADR 0106: Own native call wake through retained device registrations and one-use admission

Status: Accepted

Date: 2026-10-05

## Context

ADR 0100 provides foreground iOS and Android clients. Browser Web Push does not supply native incoming-call admission, and a provider message must not carry caller details, call contents, session credentials or a LiveKit token. A delayed notification, an old device/session generation and an uncertain provider send must fail safely.

## Decision

NotificationDelivery owns `native_push_registrations` and `native_call_wakes`, and the exact `/api/v1/me/native-push/{config,registration}` and `/api/v1/native-call-wakes/:id/admit` routes. Native registrations require a current active human, exact tenant/user/device/DeviceSession, current MFA authority, an approved application/environment/channel and registration CAS. Limited humans retain their available conversation communication; Telephony continues to require current workspace access and its own line/routing eligibility. Transport tokens are encrypted with a dedicated AES-256-GCM keyring and authenticated registration/version/channel/application/environment context. No token, token hash or ciphertext appears in a read projection or a job argument. A token cannot cross users, including after revocation. A new backend device may rebind the same tenant/user/installation registration only after the owner has disabled it and wiped its ciphertext; the retained ID and monotonically increasing version fence old wakes. The new device must have no registration and supply expected version zero. Active registrations and different installations remain unavailable. Android logout deletes/rotates the provider token for the next account; APNs does not guarantee token rotation, so account-switch wake remains unavailable until owner erasure or a new token. Provider token acquisition and deletion have bounded waits and serialized confirmation; uncertain cleanup blocks replacement registration. Android's Firebase SDK retains its own token storage, outside K-Comms preferences; K-Comms stores only nonsecret consent/installation choices and keeps received hints in bounded RAM.

The canonical governance tenant advisory fence comes first, followed by registration capacity/provenance and retained current identity locks. Each registration/wake effect checks current authority and owner eligibility under those locks. Conversation admission withdrawal belongs to the exact device/session; unrelated historical revoked admissions do not exclude a current member, and an explicit current owner-authorized readmission restores eligibility. Native ongoing media reads request the optional `current_admission=true` participant-list parameter; the actual Calls owner checks the requesting session before returning the existing safe list. Another admitted device of the same user cannot mask this session's revocation. Legacy participant list reads retain their existing member policy. The existing `NotificationCommand` gains exact session-revocation and final user-erasure variants; its implementation remains the same IdentityAccess-owned port and NotificationDelivery transaction contribution. Identity/session/device withdrawal wipes token ciphertext and terminates pending wakes in the current owner transaction. Final governance erasure removes the retained registration, fingerprint and dependent wakes.

A durable outbox event discovers recipients through the NotificationDelivery-owned `NativeCallWakePort`; the integration composition delegates to the existing Calls or Telephony owner facades. It pages eligible registrations and retains an opaque UUID intent with a horizon no later than the original event time plus 30 seconds, current session expiry and current call-owner expiry. Retries do not reset that horizon. Provider jobs contain only intent ID and registration version. A committed effect claim precedes provider I/O, so a crash, lost response or provider timeout leaves durable uncertainty and never causes automatic re-emission. The worker retains current owner locks through bounded provider I/O. Cleanup pages registrations with durable continuation jobs, expires intents and removes old intent history.

`NativePushProviderPort` uses fixed official APNs HTTP/2 and FCM HTTP v1 endpoints through the existing pinned TLS/DNS transport. APNs uses a local P-256 ES256 provider token; FCM uses a bounded RSA service-account assertion and fixed Google OAuth endpoint. Payloads contain only protocol version, opaque wake ID, expiry and the generic kind `call`. APNs device tokens necessarily occur in the provider's prescribed request path, and OAuth/FCM secrets occur only in their prescribed transport headers/body; none is logged. Provider rejection, token invalidation and uncertain network results remain distinct. Credentials and providers are OFF by default, separately from approved, operator-qualified signed application configurations. Provider status reads only the strict approved-channel configuration; it describes an approved delivery attempt and does not attest credential validity or physical delivery. Edge has the dedicated registration AEAD key but no transport credentials. Worker alone reads bounded direct regular private files under `/run/secrets` (0400 or 0600, no symlinks), validates the actual APNs/FCM keys and performs network I/O.

Native clients first fetch that real readiness contract. The unsigned iOS app has no push entitlement/background modes and `NativePushDeviceQualified=false`; Android has `NATIVE_PUSH_QUALIFIED=false`, no automatic Firebase initialization and a disabled native receiver. User consent and current advertised platform eligibility are required in addition to local signed-build qualification. PushKit immediately reports every delivered VoIP push to CallKit with a generic handle before any HTTP, permission or media operation, then ends invalid hints. Only an OS answer action resolves the one-use intent. Android receives a data-only opaque hint, confirms current authentication/configuration, and shows a private generic CallStyle notification. Its immutable action opens an unexported foreground Activity; only that explicit answer resolves the intent and starts the existing CoreTelecom/LiveKit path after microphone permission. Android calls retain the foreground lifetime policy. Neither receiver starts microphone/camera hardware or claims a phone line.

The admit route rechecks exact current registration/session/user version, call-owner authority, active status and TTL, then consumes the intent atomically with the existing owner admission and credential issuer. A foreign, expired or replayed ID produces a neutral unavailable response. API results and SDK callbacks are fenced by the current local identity generation. Media retains the existing periodic current `/me`, call/participant or Telephony device-lease checks and expiry watchdogs; legitimate role metadata changes do not blanket-log out a valid human.

The release capability is exactly `native_call_wake_v1`. Rollback hazards count **all** retained registration and wake rows plus exact available/scheduled/executing/retryable `NativeCallWakeWorker` and `NativePushReconcilerWorker` jobs, including orphans. Migration `20261006000600` refuses before DDL if any such state remains. The inherited fourteen capabilities remain exact; the wake-only union has fifteen. Existing strict parsing is unchanged.

## Consequences and qualification

Source tests exercise privacy, AEAD context, CAS/current generation, one-use resolution, expiry, provider uncertainty, identity erasure and rollback refusal. Actual backend, Android and macOS runners must qualify this wake source separately from the foreground client parent. Signed-device APNs/FCM delivery, locked-device Keychain access, OEM background delivery, CallKit/CoreTelecom focus and permission behavior remain unqualified until physical test receipts exist. Keychain's existing device-only unlocked policy remains intact; an unavailable locked credential fails the answer closed. No physical ringing or production readiness is asserted by source, mocked providers, an unsigned build or a configured provider flag.

## Exact boundary review

The wake transition binds to the immutable native parent manifest and approves only its enumerated new DTOs, owned tables/key box, two consumer-owned ports, two consumed call events, the governance-erasure caller on the unchanged identity notification operation, and the regenerated exact facade operation inventory. Parent member contracts already present in that native base retain their ownership and access declarations. No generic dependency edge or persistence-access exception is added.
