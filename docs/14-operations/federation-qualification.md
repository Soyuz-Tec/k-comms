# Federation qualification and pending-proof operations

Federation defaults to disabled. Before enabling, configure and qualify a maintained Matrix/Synapse release, its real standard server-federation routing/TLS/discovery/allowlist controls, a non-admin bridge account and private secure credentials. The K-Comms adapter connects only to one pinned public HTTPS origin and never performs custom server federation signing. FEDERATION_PROVIDER_QUALIFIED is a reviewed operator declaration, not automated provider evidence.

The declared FEDERATION_LOCAL_RESIDENCY and per-domain residency/reason do not attest actual remote storage geography. Operators must evaluate the actual homeserver and remote provider arrangements independently before approving a domain. No source test uses a live provider.

Source qualification must merge the complete shared IdentityAccess Matrix mapping implementation and its 01000 migration from ADR-0104 before compiling and running Federation tests. The copied MatrixIdentityView and exact Accounts delegate are binding source only; the shared implementation is not duplicated in this tree. Then run focused backend, Matrix protocol, HTTP and web tests; all migration-forward, disposable empty 00900 down/up, retained-row down refusal, current-binary legacy-capability refusal, real two-account consent/membership/revocation contention, bounded deadlines and Governance hold/erase controls. Preserve unrelated source rows and parent migration bytes. Do not globally reset/drop a database.

Use two real synthetic accounts/workspaces and maintained configured synthetic homeservers for final HTTP/browser/provider federation acceptance. Demonstrate actual remote invitation acceptance, explicit local consent, bridge message sync, domain mismatch rejection, room encryption refusal, current proof expiry/revocation, denied stale CAS, provider restart and lost create acknowledgement recovery. Capture light/dark desktop and 390px screens with private no-store responses and no horizontal overflow. No API mocks qualify this acceptance. Pin source/helper hashes before and after and retain every failed attempt receipt.

If deletion is requested, the real Governance worker must retain a completion barrier until provider proof exists. Matrix local redaction/leave does not prove global remote deletion. The present adapter therefore retains remote_unconfirmed obligations and never issues a completed remote deletion receipt. Provider failure, expired credentials and unknown bridge-send or create outcomes remain pending. A hold blocks destructive cleanup. Re-enabling a trust cannot restore a fenced room. Ordinary logout preserves offline consent but does not authorize executing queued current-session commands.

The configured canonical HTTPS origin and Matrix server_name are separate values and must match the shared identity owner configuration. Existing rooms retain both values; changing either refuses all effects, including cleanup, without discarding old obligations. Credential files contain exactly one token and no trailing control bytes. The envelope key is dedicated to this bridge and must be retained in secure recovery configuration while encrypted lineage or obligations exist. Replacing it without a reviewed re-encryption/recovery procedure can make pending provider cleanup impossible. Never expose the key or bridge token through a client session, export or logs. The non-admin bridge token cannot be used as a client crypto/device session.

Runtime rollback requires workspace_federation_v1 while any of the five Federation tables or runnable registered Federation command jobs remains. Source migration down refuses retained state even if the associated User/Conversation is erased or unavailable. Source fingerprints include all five inventories. Production release approval and provider qualification remain separate from accepted architecture and source-only checks.
