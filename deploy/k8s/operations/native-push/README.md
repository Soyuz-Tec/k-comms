# Qualify a native call wake deployment

[ADR 0106](../../../../docs/02-architecture/adr/0106-native-call-wake-owner-protocol.md) owns this protocol. The base, local release and generated Proxmox profile keep native wake and its providers OFF. Registration readiness describes an approved attempt, and does not prove credential validity, physical delivery or ringing.

Before enablement, retain the exact application/backend digest, provider/application environment, current-device permissions, operator approval and signed physical-device receipts. Test denied and withdrawn permissions, account replacement, locked credentials, expired/replayed hints, terminated calls, caller eligibility withdrawal, provider uncertainty and governance erasure. Keep the same fifteen exact rollback capabilities while retained native registrations/intents or active native jobs exist; deleting jobs alone does not erase provenance.

Edge and Worker both need a dedicated 32-byte `NATIVE_PUSH_ENCRYPTION_KEY`, or the versioned `NATIVE_PUSH_ENCRYPTION_KEYS` keyring plus its current key ID. It must differ from browser push, identity, webhook and other security material. Edge must never receive native transport file bindings or credentials. In an operator overlay, apply [provider-worker-patch.yaml](provider-worker-patch.yaml) only to Worker, bind its init image to the same immutable release digest, and import these Secrets through the approved external secret controller:

- `k-comms-native-provider-settings`: public APNs `NATIVE_PUSH_APNS_KEY_ID` and `NATIVE_PUSH_APNS_TEAM_ID` when using APNs.
- `k-comms-native-provider-credentials`: `native-apns.p8` (P-256 APNs private key) and/or `native-fcm.json` (RSA Google service account for the exact approved project).

Kubernetes projects Secret files as symlinks. The bounded init container copies only the two fixed names into a memory volume as regular 0600 files, under the existing nonroot UID/GID. Worker mounts that volume read-only at `/run/secrets`. Edge has neither volume. Providers reject symlinks, traversal, nonprivate permissions, nonregular files, empty or larger-than-16-KiB material. Do not put key contents in environment variables, configuration JSON, job arguments, URLs, logs or receipts. A monolithic Proxmox application (`K_COMMS_ROLE=all`) contains Worker authority; mount the same two approved private regular files into that application container through an operator overlay.

After those receipts, the common runtime policy can set both `NATIVE_PUSH_ENABLED=true` and `NATIVE_PUSH_PROVIDER_ENABLED=true` with the exact approved applications in `NATIVE_PUSH_PLATFORM_CONFIGS_JSON`. Each entry has exactly `platform`, `channel`, `application_id`, `environment`, `device_qualified`; the latter is an operator qualification assertion. iOS supports `apns_voip` (and the provider's generic `apns_alert` channel); Android supports `fcm` in `production`. No native client trusts that assertion to override its own signed-build qualification. Missing/invalid Worker credentials still fail delivery safely.

For iOS, the operator must supply reviewed PushKit/APNs entitlements, VoIP background mode, the exact bundle/application environment and `NativePushDeviceQualified=true` in the signed build. The unsigned checked-in project supplies none. Every VoIP push is reported to CallKit before HTTP or hardware; only an explicit OS answer resolves the opaque intent. Keychain remains device-only and accessible when unlocked, so unavailable locked credentials fail the answer closed. PushKit does not guarantee a new APNs token after logout. An unchanged token bound to another user is deliberately refused until verified owner erasure or a new provider token; foreground communication remains available. Do not present account-switch background delivery as qualified.

For Android, use the pinned Firebase Messaging 24.1.2 dependency, reviewed signed distribution and `-PnativePushQualified=true` with public project settings `nativeFcm_application_id`, `nativeFcm_project_id`, `nativeFcm_sender_id`, `nativeFcm_api_key`. These public identifiers do not replace Worker credentials. The default build has no Firebase auto initialization and disabled receiver components. Current authentication, backend policy, user consent and notification/microphone permissions gate registration and a private generic notification. An immutable action opens an unexported foreground Activity; it never starts hardware from the receiver. Firebase's SDK owns its token persistence. K-Comms stores nonsecret choices and bounded opaque RAM hints; token deletion/acquisition is serialized, bounded and confirmed before a new identity registers.

APNs HTTP/2 uses fixed official Apple hosts, ES256 headers and a payload containing only protocol version, opaque wake UUID, expiry and generic kind. FCM uses fixed Google OAuth/HTTP-v1 hosts and the same data-only fields. The prescribed provider transport alone receives device tokens. All provider I/O retains one total deadline and existing pinned DNS/TLS restrictions. Provider response loss remains durable uncertainty and does not authorize automatic resend. No provider purchase, credential import, signed distribution or physical delivery is performed by this source change.
